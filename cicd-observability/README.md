# 🚦 Track 3: CI/CD, Automation, Monitoring & Observability (Unit 4)

**From "it works on my laptop" to "every commit is tested, scanned, shipped, watched, and someone is told when it breaks".**

You will build a small delivery factory (Git → Jenkins → registry → staging → production) and a full observability platform (Prometheus, Alertmanager, Grafana, Loki, Jaeger), then break things on purpose and fix them like an on-call engineer. Everything runs on **Docker Desktop or any Docker engine with Compose**. No cloud account, no Kubernetes needed (though [K20](../kubernetes/20-projects/README.md) shows the same ideas inside a cluster).

```
  ☕ one tiny app, the Chai Stall → ships through a pipeline you can read → is watched by a platform you can query
  🚦 a failing test, a leaked secret and a buggy canary each get stopped by a different gate
  🔔 break production on purpose → an alert email arrives before you finish typing → follow the failed request from graph to log line to trace
```

Unit 4 of the Christ University DevOps course, but anyone can follow it. ## 🧰 Before you start (10 minutes)
```bash
git clone https://github.com/vellankikoti/docker-k8s-zero-to-hero.git     # skip if you already have it. Do NOT use --depth: Jenkins needs the full history
cd docker-k8s-zero-to-hero
./cicd-observability/scripts/doctor.sh        # checks Docker, Compose, free ports, memory
```
`doctor.sh` prints a ✔ or ✖ for each requirement and tells you how to fix every ✖. Plan on **4 GB free memory per project** (run them one at a time on a small laptop).

## ☕ The star of the show: the Chai Stall
Every lab uses one small service, [`app/`](app/): ~230 lines of standard-library Python, no `pip install`. It behaves like a real production service:

| Endpoint | What it shows |
|---|---|
| `POST /order?item=chai` | a business action, counted in `orders_total` |
| `GET /metrics` | **Prometheus metrics**: request counts, a latency histogram, orders, in-flight requests |
| stdout | **JSON logs**, one object per line, with a `trace_id` |
| OTLP spans | **traces**, sent to Jaeger when `OTEL_EXPORTER_OTLP_ENDPOINT` is set |
| `GET /healthz`, `/readyz` | liveness and readiness |
| `POST /chaos?error_rate=0.3&latency_ms=400` | 💥 break it on purpose: errors and slowness for incident practice |
| `SIGTERM` | shuts down gracefully, which is what makes rolling updates lossless |

Run its tests: `cd cicd-observability/app && python3 -m unittest discover -s tests -v`

## 🧭 How every lab is built
🎯 what you'll learn → 🧠 the concept in 60 seconds (with a diagram) → 🧪 hands-on steps with expected output → 🏭 what changes in production → 🏆 a challenge (answer hidden) → ✅ checkpoint quiz (answers hidden) → 🧹 cleanup

Projects add one thing: after each phase, run `./scripts/verify.sh N` and get a ✔ or ✖ with a hint. Nobody has to guess whether they did it right.

## 🧹 Cleaning up (always safe, never touches your other labs)
```bash
cd cicd-observability/projects/project-1-ship-it
./deploy/deploy.sh clean          # removes the app containers the pipeline deployed (they are not part of Compose)
docker compose down -v            # removes Jenkins, the registry, the router and their data
cd ../project-2-see-everything
docker compose down -v            # (add -f docker-compose.shipit.yml if you used that add-on)
docker image prune -f
```
